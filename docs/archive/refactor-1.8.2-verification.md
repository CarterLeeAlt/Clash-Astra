## 真实 Mihomo 隔离验证

通过进程级 `ASTRA_TEST_SUBSCRIPTION_FILE` 指定工作区内的测试订阅，然后运行：

```powershell
node scripts/pnpm.mjs exec cargo test --manifest-path src-tauri/Cargo.toml subscription_compile_reload_and_http_rejection -- --ignored --nocapture
```

结果：单独运行的集成测试通过，涵盖以下断言：

- 读取用户授权的测试订阅、经项目编译器生成配置，并由真实 Mihomo 校验。
- 在独立工作目录、随机空闲监听端口启动 Mihomo，控制器就绪且代理表可读取。
- PATCH 模式生效；错误访问密钥被控制器拒绝。
- 无效内核配置被拒绝后，文件内容与实际内核模式恢复，候选状态不发布。
- 有效配置已被内核接受、但注入提交失败后，文件内容与实际内核模式恢复。
- 正常重载和文件事务提交成功。

为避免把控制接口回归变成对远程规则库可用性的测试，保留订阅节点和分组，使用固定本地规则并关闭该隔离内核的 DNS 监听。该测试不是远程节点连通性、吞吐或服务质量测试。

测试进程由 RAII 守卫结束，不接管 Windows 系统代理、不安装服务、不修改防火墙或用户运行实例。订阅来源地址、节点凭据和结果配置不写入本记录或仓库；含敏感内容的临时集成目录在完成后移入回收站。
