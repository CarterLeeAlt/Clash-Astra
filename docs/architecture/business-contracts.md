# 业务行为与重构验收

## 行为基线

基线提交：`86ecfebc907f887bb2769c380b14bffe4298b263`。技术栈为 React 18、Tauri 1、Rust，运行平台为 Windows。

| 业务     | 契约                                                                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 订阅     | remote/local 可激活；merge/script 是增强项；固定全局脚本先于用户增强链执行                                                                        |
| 配置     | 已提交快照是持久化意图的读取来源；候选状态属于单次操作；提交前失败恢复旧状态；提交后应用核验失败返回 `APPLY_INCOMPLETE`，运行界面读取内核实际状态 |
| 端口     | 一次保存接收全部端口，内核与系统代理使用同一个目标配置                                                                                            |
| 节点选择 | 核心选择、相关旧会话清理与订阅中的选择记录由同一操作协调；订阅重载、启动及恢复后恢复有效选择                                                      |
| 自动更新 | 新建、修改、删除订阅后的调度任务集合与已提交订阅一致                                                                                              |
| 实时数据 | 旧连接、旧请求和旧测试轮次不能覆盖当前代次；断线轮询在 WS 恢复后结束                                                                              |
| 窗口     | 关闭隐藏；显式显示优先于旧隐藏请求；退出后不接受恢复任务                                                                                          |
| 持久化   | 保留现有 YAML 字段和配置目录；跨文件变更具有恢复记录                                                                                              |

## 即时生效与恢复

| 变更                         | 内核动作与完成条件                                                                                       |
| ---------------------------- | -------------------------------------------------------------------------------------------------------- |
| 节点                         | `PUT /proxies/{group}`；回读目标选择；按该分组、原路径和连接 ID 清理旧 TCP／UDP 会话；正常路径保持原进程 |
| 规则／全局／直连模式         | `PATCH /configs`；回读实际模式；清理切换前及应用期间建立的相关旧会话                                     |
| 订阅、覆写、DNS、TUN         | 校验并完整重载；等待 Provider 就绪、恢复有效选择、核验配置和监听，清理旧会话                             |
| 监听端口、局域网访问         | 热更新；核对配置与 TCP 监听；系统代理启用时同步目标端口并回读 Windows 状态                               |
| 控制地址、密钥、服务托管方式 | 重启；等待控制器与订阅就绪，恢复选择并核验实际运行配置                                                   |
| 随机端口                     | 分配可用端口并立即应用，不以“重启后生效”作为完成反馈                                                     |
| 应用日志等级                 | 热更新应用日志配置；内核日志等级单独更新                                                                 |
| Provider／Geo 数据           | 由后端协调更新、重载和核验；下载请求使用独立的有界超时                                                   |

节点和模式切换共用一次 **7 秒**截止时间，从点击开始覆盖前端排队、IPC 传递、后端操作门闩、API、重试、恢复及最终核验。前端将原始绝对截止时间传至后端，不在进入 IPC 或恢复时重新计时。正常 API 阶段约至第 4 秒，为至多一次受控内核恢复保留约 3 秒；最终不能核实成功时返回失败。

瞬时失败按 **50、100、150、200 ms**等待后重试，后续等待上限为 **200 ms**。删除连接后必须重新查询连接表；HTTP 204 本身不证明会话已关闭。固定 Mihomo 的空连接表以 `connections: null` 表示，缺少整个字段属于无效回读。连接 UUID 作为 URL 路径段构造，保留其中的连字符。

### 普通操作预算与确认

所有产品关键操作的超时上限为 **60 秒**，嵌套调用继承原截止时间，排队、重试、核验和补偿不重新计时。节点／模式仍使用上述 7 秒专用预算。普通操作预留最后 5 秒用于补偿；调用方超时不会提前释放仍在处理一致性清理的写入门闩。

| 操作或阶段                                             | 上限                                            | 完成条件                                                                                     |
| ------------------------------------------------------ | ----------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 普通配置修改、订阅激活、手动重启                       | 总计 30 秒                                      | 配置、监听和受影响运行内容读回符合候选状态                                                   |
| 订阅导入／下载更新、Provider／Geo 更新、服务安装／卸载 | 总计 60 秒                                      | 下载／helper 完成后，继续在同一预算内应用与核验                                              |
| 订阅下载阶段                                           | 40 秒；单次请求 15 秒、连接 8 秒；最多 3 次     | 响应正文完整、格式和版本有效；瞬时失败才重试，保留原代理及证书策略                           |
| Provider／Geo 更新请求                                 | 40 秒                                           | Provider 的 `updatedAt` 推进且内容有效；Geo 至少一个本地数据文件在本次操作中更新、非空且可读 |
| Mihomo 配置校验                                        | 10 秒                                           | 校验进程退出且退出码为成功；超时终止自建进程                                                 |
| Windows helper／UAC 等待                               | 45 秒且受剩余预算约束                           | helper 成功后读回目标状态；helper 自身检查原始绝对截止时间，拒绝迟到授权后的过期写入         |
| `sc.exe`／SID 查询                                     | 单次 3 秒                                       | 命令成功且状态可解析；查询失败不能冒充未安装或已停止                                         |
| TUN 网卡与路由收敛                                     | 5 秒                                            | 有界重查实际网卡和路由，而非反复切换 TUN                                                     |
| 手动关闭连接                                           | 后端取得门闩后最多 7 秒，仍受普通操作总预算约束 | 只清理操作时捕获的目标 ID，并重查其消失；不追删操作后新建的连接                              |

鉴权、参数和配置校验错误不重试、不因此重启。响应丢失不等于写入失败：配置／节点写入先读回目标再决定是否重试，Provider 下载不因响应丢失重复提交。代理／规则 Provider 均从集合接口按名称回读，固定内核不提供单个规则 Provider 的 GET。服务停止必须确认原受管子进程退出，失败时保留进程归属；服务安装核对 SCM 存在性和实际二进制路径，不要求按需服务已运行。

系统代理恢复只核验仍属本应用的字段，外部软件更改的字段保持原样；恢复核验失败保留恢复记录和归属，不返回成功。自动补偿不重复弹 UAC。调用方整体超时使用 `OPERATION_TIMEOUT`，事务阶段失败沿用带阶段和补偿结果的错误；已提交但不能证明应用完成使用 `APPLY_INCOMPLETE`，补偿失败使用 `RECOVERY_INCOMPLETE`。

完整重载检查内核代理／分组名称、类型、显式成员，以及规则数量、顺序、类型、普通规则目标和载荷；CIDR 按网络地址比较。逻辑规则内部表达式、DNS 上游实际使用情况，以及 Geo 是否为远端最新版本不由这些接口直接证明，不能用本地候选文件冒充运行时读回。Geo 时间戳证明的是本次本地文件写入，不是远端内容的新鲜度证明。Windows 原生调用若仍在返回途中，一致性清理继续保留门闩，界面超时不能被解释为系统调用已强制取消。

连续点击串行执行，待执行项保留最后一次意图；被后续点击替代的排队项不进入 IPC。排队耗尽预算时明确失败。超时调用返回后，工作线程仍持有操作门闩完成文件补偿；截止时间之后不启动新的切换 API 写入，也不通过补偿触发第二次内核重启。运行时代次用于失效控制器、代理、规则、Provider、连接与测速缓存。

路由关键变更固定处理旧会话，没有关闭此行为的应用设置。节点清理保护其他分组以及已走新路径的连接。TUN 界面管理字段优先于订阅同名字段，订阅其他字段保留；Windows TUN 启停还需查询指定设备的实际适配器和路由，不能仅凭配置接口成功判定。

## 回归场景

- 候选配置的并发读取、并发写入、校验拒绝、外部执行失败、保存失败、补偿失败。
- 删除当前订阅、删除最后一个普通订阅、无效排序 ID、增强链引用清理。
- 系统代理开启时修改端口；端口边界和重复监听端口校验。
- 新建与删除带自动更新周期的订阅。
- 快速切换订阅、节点恢复失败、控制器 HTTP 拒绝。
- 连续节点／模式点击、排队耗尽预算、IPC 传递耗时、超时后操作门闩与禁止迟到写入。
- 删除接口前两次失败、204 假成功、最后一条连接关闭后的空连接表、一次恢复及切换前读取失败后的恢复。
- 真实内核的旧 TCP 长连接与 UDP 会话清理、其他分组连接保护、正常切换保持进程、恢复后选择保持。
- TUN 枚举和省略的 false 字段回读、界面字段优先级、IPv4／IPv6 与禁用适配器的路由判据。
- 普通操作及嵌套预算不超过 60 秒、恢复预留、调用方超时后的门闩保留和禁止迟到写入。
- 校验子进程挂起、非零退出、迟到授权预算失效、服务停止失败时保留子进程归属。
- 鉴权错误只请求一次、写响应丢失后读回成功不重复写、Provider 假成功与过期数据拒绝。
- 系统代理恢复字段不一致拒绝成功、外部修改字段保护、手动连接关闭确认前不清空界面。
- WS 恢复期间仍有 HTTP 请求在执行；隐藏、卸载、重连与旧请求完成交错。
- 控制器初始化失败、并发初始化与旧初始化晚完成。
- 窗口显示、隐藏、重建、正常退出与 Watchdog 恢复。

## 验证边界

纯业务与失败注入测试使用内存替身或工作区临时目录，不读写用户运行实例。生产协调器回归使用独立应用目录、本地合成节点、真实固定内核与故障注入控制器；前端实渲染使用实际组件与合成 IPC。用户订阅属于集成验证输入，不进入仓库、日志正文或测试快照。Windows 服务、系统代理写入、TUN 驱动与系统路由的真实副作用验收需另行记录测试实例、前后状态与恢复结果，纯回读判据测试不等于这些宿主副作用已实测。

系统代理库完整测试只允许只读平台检查和生产逻辑纯单元测试，不包含真实代理写入目标。禁用断言遵守空地址、端口 `0` 的接口语义；生产恢复核验通过内存输入覆盖归属字段不一致拒绝成功、外部修改保护、有限重试与持续查询失败。纯单元测试不能替代真实宿主验收，实际网络变更须另行获准并留存操作前状态。
